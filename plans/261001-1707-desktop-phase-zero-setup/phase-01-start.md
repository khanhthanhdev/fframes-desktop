# Phase 1: Bootstrap the native desktop spike

## Goal

Create the smallest isolated GPUI desktop workspace that proves native startup, editable IME-aware text, and explicit RGBA-to-GPUI image presentation without pulling GPUI or a second event loop into the fframes workspace.

## Context and verified constraints

- M0 requires a coherent GPUI revision and working window, input/IME and image presentation, not initialization alone ([implementation-plan.md:40-42](../../docs/desktop/implementation-plan.md#L40)).
- GPUI must own the only UI event loop; builds and rendering remain outside it ([architecture.md:43-70](../../docs/desktop/architecture.md#L43)). The native winit player is only a reference and must not be embedded ([research.md:138-142](../../docs/desktop/research.md#L138)).
- The current root is a resolver-2 workspace with no desktop exclusion or GPUI packages ([Cargo.toml:1-51](../../Cargo.toml#L1)). Add `exclude = ["desktop"]`, then give `desktop/` its own manifest, lockfile, and toolchain.
- Use source-listed historical Zed commit `1a84d5d92bd7d6c1cabb116062650af545783fe9` as the initial same-revision candidate for `gpui` and `gpui_platform`; it is unqualified until these checks pass ([GPUI report:16-28](../reports/researcher-261001-1707-gpui-phase-zero.md#L16)). Use Rust `1.98.1` as the candidate compiler, also subject to qualification ([GPUI report:81-86](../reports/researcher-261001-1707-gpui-phase-zero.md#L81)).
- Linux enables `x11` and `wayland`, macOS enables `font-kit`, and Windows uses the MSVC target without an extra GPUI platform feature ([GPUI report:66-79](../reports/researcher-261001-1707-gpui-phase-zero.md#L66)). A successful fframes CPU render does not establish that GPUI can present it: GPUI still needs a compatible native graphics backend and driver.
- GPUI `RenderImage` is BGRA while `fframes::RgbaFrame` is straight RGBA ([GPUI report:165-173](../reports/researcher-261001-1707-gpui-phase-zero.md#L165), [preview.rs:16-22](../../fframes/src/renderer/preview.rs#L16)). The protocol must carry channel and alpha semantics, and the app must convert once at presentation.

## Protocol and data flow

Define the initial frame envelope before presenting pixels:

```text
FrameHeader {
  protocol_version, source_revision, worker_generation, request_id,
  frame_index, width, height, stride_bytes,
  channel_order: Rgba8 | Bgra8,
  alpha_mode: Straight | Premultiplied,
  color_space: Srgb,
  payload_len
}
```

Validation rejects zero/overflowing dimensions, `stride_bytes < width * 4`, a payload whose length differs from `stride_bytes * height`, unsupported enum/version values, and any frame above a fixed Phase 0 limit (start with 64 MiB and record the reason if qualification changes it). The static test source emits straight RGBA with transparent and semitransparent reference pixels. `frame_image.rs` removes row padding, converts RGBA to the exact pinned GPUI BGRA/alpha contract, uploads on the GPUI thread, replaces the previous image, and decrements the resident-image counter. No unbounded queue exists in this phase.

BGRA storage alone does not establish alpha, stride or lifetime semantics. Inspect the candidate's actual upload path and record the complete contract. Keep a native screenshot/readback fixture with transparent, half-transparent and opaque pixels plus padded rows. Track real GPUI image IDs and the pinned window/cache release operations when replacing images. Measure process and available graphics/cache memory through the 1,000-replacement run; a manually decremented logical counter alone cannot pass the resource gate. If GPU eviction cannot be observed directly, record the missing metric and obtain pinned-cache/release evidence before claiming bounded resource behavior.

Text input implements the pinned `EntityInputHandler` contract rather than a keypress-only field: marked text, UTF-16 selection/replacement, caret bounds, paste, commit, and composition cancel. The UI shows the committed string and composition state so native manual tests are observable.

2. **Create minimal shared boundaries.**
   - [x] Implement serializable protocol version, request identity, revision/generation identity, frame header and bounded validation in `fframes-studio-protocol`.
   - [x] Implement an app-local `ChildEnvironment` in `studio-bootstrap` that starts from an explicit allowlist plus SDK values, never writes global `PATH`, and tracks command, PID, and ownership handle for every child. Linux/macOS use an owned session/process group; Windows uses a kill-on-close Job Object with assignment before execution. Assignment failure prevents launch, and breakaway children are unsupported until qualified. Graceful cancellation has a bounded drain before termination; success requires no remaining owned descendants.
   - [x] Unit test malformed lengths, overflow, unsupported channel/alpha/color modes, stale generation identity, and the 64 MiB cap.

3. **Build the GPUI spike.**
   - [x] Start through `gpui_platform::application()` and open one ordinary opaque window.
   - [x] Add one focusable composer field implementing composition/marked text, UTF-16 selection and caret reporting.
   - [x] Present a generated color/alpha reference image through a single measured conversion path; show dimensions, last conversion/upload duration, resident images, and queue depth in the window.
   - [x] Replace images with queue depth fixed at one, invoke the pinned GPUI release/cache removal path for the prior image ID, and measure real cache/process/available graphics memory. Keep conversion off the UI loop; publish presentation state on it.
   - [x] Close cleanly and prove the bootstrap owner has no child process left.

4. **Run the first native gate on Linux x64, then compile on the other targets.**
   - [x] On a real Linux desktop, run once under X11 and once under Wayland; type composed Vietnamese plus one CJK input sequence, move the candidate window, paste, select and delete text, resize, replace 1,000 images, then close.
   - [x] Record compositor, GPU/driver, GPUI backend, font, conversion/upload latency and memory before/after image replacement. Test any available GPUI software/fallback mode separately; do not describe fframes CPU rendering as GPUI fallback support.
   - [x] Run native compile checks on Windows x64 MSVC and macOS arm64. Runtime input/image checks are completed in Phase 3 after managed setup artifacts exist.

Root metadata must exclude every desktop crate. Desktop metadata must show the exact candidate revision once for each GPUI package. Tests must exercise conversion without a GUI. The final command is a proposed Phase 0 app mode and passes only through manual/native evidence; a headless launch or screenshot is insufficient.

Native evidence commands follow the report recipes: Linux records X11/Wayland and dynamic dependencies ([GPUI report:211-226](../reports/researcher-261001-1707-gpui-phase-zero.md#L211)); Windows runs from Developer PowerShell and captures `cl`, `link`, `rc`, SDK and `dumpbin` output ([GPUI report:228-243](../reports/researcher-261001-1707-gpui-phase-zero.md#L228)); macOS records Xcode/Metal and `otool` output on arm64 ([GPUI report:245-262](../reports/researcher-261001-1707-gpui-phase-zero.md#L245)).

## Pass/fail gate

Pass Phase 1 only when Linux x64 opens on both available backends, committed/composed text behaves correctly, the reference pixels match after upload, 1,000 replacements keep queue depth at one without continuous resident-image growth, and close returns with no owned child. Windows/macOS compilation must have a named native result; runtime remains pending until Phase 3.

Stop and replan the GPUI choice if the candidate revision cannot produce window + IME + image on Linux after one bounded compatibility fix, requires a long-lived fork, or cannot keep blocking work off the UI thread. A missing GPU/backend is a failed host prerequisite result, not a successful CPU-renderer result.

## Risks, mitigation, and rollback

| Risk | Likelihood × impact | Signal / mitigation | Rollback |
|---|---|---|---|
| Candidate revision or Rust pin is incompatible | Medium × High | Recheck upstream manifests, allow one documented pin adjustment, then rerun lock/tree/runtime gates. | Revert only desktop pin/lock changes; root core remains unaffected. |
| IME looks like typing but composition is broken | Medium × High | Test marked text, UTF-16 replacement and candidate positioning with two real IMEs per native target. | Keep M0 blocked; do not substitute a basic key handler. |
| Pixel colors/alpha are wrong | High × Medium | Golden 2×2 and padded-row tests plus native screenshot/sample comparison; convert once to GPUI BGRA. | Disable worker presentation and retain diagnostic reference image until contract is fixed. |
| Image replacement leaks GPU resources | Medium × High | Expose queue/resident counts and measure 1,000 replacements. | Keep a single static image spike; do not proceed to worker playback. |
| Nested workspace contaminates root build | Low × High | Compare both metadata graphs and run root checks. | Remove the root exclusion and `desktop/` directory together; no core dependency should remain. |

## Security and compatibility

This app runs no downloaded project yet. Still, protocol lengths must be checked before allocation and process ownership must use exact PIDs/process groups, never broad kill patterns. GPUI and Rust pins remain compatibility-manifest inputs in Phase 2. Phase 1 changes no public fframes API and has no migration requirement; deleting the isolated workspace restores prior behavior.

## Current implementation

### Owners and conversion

- There are no `desktop/crates/studio-preview` or `studio-worker` crates. The actual protocol/runtime owners are `fframes-studio-protocol/src/preview.rs`, `fframes-studio-runtime/src/preview_worker.rs`; app transport is `desktop/app/src/preview_worker_client.rs`.
- `Svgr` has compile-time nested-document and runtime string representations (`fframes/src/svgr.rs:5`). `into_svg_tree` uses `Tree::from_nested_svgtree_with_cache` or `Tree::from_str` (`:16`, `:27`). `as_subtree` and `FromIterator` concatenate nested nodes, without provenance (`:37`, `:109`). Any sidecar must survive these composition paths as well as string fallback.
- `svgr!` constructs either representation (`svgr-macro/src/lib.rs:34`, `:57`, `:83`). `parse_svgr_subtree` calls `Svgr::from(...).as_subtree()` (`svgr-macro/src/nodes_to_svgtree.rs:831`). Unknown attributes are rejected through `AId::from_str` (`:752`); arbitrary `data-editor-*` metadata cannot simply be inserted. `MaybeNodeData` carries render cache `static_hash` (`:272`), which is neither semantic identity nor instance identity.
- Pinned conversion dependency is `usvgr = "0.46.0"` (`Cargo.toml:105`). Locally installed dependency source provides stronger evidence than a conjectured SVG contract: `/root/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/usvgr-0.46.0/src/parser/converter.rs:621` preserves IDs only on `<g>`/`<use>` groups outside marker expansion (`:643`) and retains g/use via its `required` predicate (`:735`). Text IDs survive as Text (`parser/text.rs:118`); marker-generated IDs are intentionally removed. `tree/mod.rs:1817` `node_by_id` finds the first matching ID, so it cannot disambiguate repeated IDs. These are source observations, not an empirical survival qualification.

### Scenes, bounds and ordering

- `Scene::name` defaults to Rust type name; `SceneInfo` carries timeline index/ranges only (`fframes/src/scenes.rs:31`, `:48`, `:63`). `ResolvedScenesTimeline::from_scenes` enumerates scene references and resolves overlaps (`fframes/src/video.rs:83`, `:97`). `FFramesContext::render_scenes` concatenates every active scene in timeline order (`fframes/src/fframes_context.rs:110`); `get_scene_info` uses pointer equality (`:128`), unsuitable as durable occurrence identity when a reference is reused.
- `SceneReport` has index/name/full_name/range but no semantic instance ID (`fframes/src/renderer/preview.rs:193`). Active preview currently synthesizes `source_revision:scene:index` (`fframes-studio-runtime/src/preview_worker.rs:220`). This is valid revision-local timeline identity for M4, not the stable registered M5 identity.
- `Previewer::svg_tree` performs the actual render and conversion (`fframes/src/renderer/preview.rs:392`). `render_inspected` shares one converted tree for diagnostics and pixels (`:451`), the natural hook for consistent frame metadata. `FrameReport` is diagnostics/scenes, not object geometry (`:214`). `inspect_tree` currently traverses transformed groups/text for diagnostics (`fframes/src/diagnostics.rs:215`, `:227`); it is not a hit-test index.
- Converted nodes expose absolute transforms and bounds, including stroke bounds (`usvgr tree/mod.rs:995`, `:1036`, `:1255`, `:1322`). Skia traverses children in order (`fframes-skia-renderer/src/render/mod.rs:222`), flattening Text only for painting (`:238`). `Path::paint_order` is fill/stroke order, not global object z-order. Metadata should enumerate actual traversal and retain group hierarchy; clip/mask/opacity/filter effects need explicit conservative flags.
- `fit_transform` scales tree coordinates independently in x/y to raster size (`fframes/src/renderer/preview.rs:82`). Tree bounds cannot be called video pixels without accounting for tree size versus `Video::WIDTH/HEIGHT`; scaled previews introduce a further fit, and GPUI letterboxing another.

## Proposed additive representation (not implemented)

1. Opt-in source registration separate from render geometry: semantic scene occurrence, component/object ID, explicit repeat instance key, source path/symbol/hash and optional registered span; parent identity, text/media/token bindings. Do not reuse static_hash or revision:index as semantic identity. Preserve unannotated imported projects through scene/range fallback.
2. Spike an explicit `<g id={encoded_unique_render_id}>` envelope for an annotated subtree plus a typed registration sidecar mapping opaque render ID to semantic tuple. The converted group evidence makes this a promising candidate, not the final chosen syntax. Avoid treating arbitrary SVG IDs as source anchors. Encode the tuple collision-free and validate duplicates. Registration must support repeated occurrences of the same Rust scene type/reference and generated SVG lists. Compare envelope approach against sidecar carried through `Svgr` composition; choose only after empirical gates.
3. Add a frame metadata collection path using the exact converted tree rendered to pixels. Emit finite video-coordinate bounds, visibility/support flags, parent/group relationships and deterministic traversal rank. Treat masks/clips/shaders/video as conservative layer scope; expose rectangle/scene fallback. Separate stable revision editor index (source registrations) from frame geometry.
4. Negotiate an additive selection capability in preview handshake. A metadata-bearing frame response or request keyed to an immutable displayed frame must carry envelope, frame index, seek serial and bounded editor-index identity. Couple installation to the same presented pixel frame; reject late, old-session, old-generation and changed-style/assets results. Keep the legacy v1 route compatible. Bound object counts, hierarchy depth, strings, serialized bytes and frame-cache retention; explicit overflow is fallback, never silent exact selection.
5. Implement UI-independent inverse letterbox/zoom/pan mapping using actual image geometry, then topmost leaf selection and deterministic group/overlap cycling. Frozen task packet must retain full semantic tuple and exact displayed identity rather than only `SelectedElementInfo.element_id`.

## Proof gates before selecting representation

- Both conversion representations: rect/path/text/image and explicit group IDs survive; marker/use expansions either preserve unique ownership or are flagged unsupported. Text layout/flattening and converter cache must not erase registered ownership.
- Repeated scene types, the same scene reference twice, repeated SVG subtrees, nested helper composition and dynamic lists yield distinct stable identities. Reordering/deleting instances never redirects a deleted selection to a different object.
- Bounds and order: animated nested transforms, viewBox/physical dimension mismatch, preview scale and output fit; strokes; groups; crossfade overlap; clipping/masking/opacity; shaders/video layer fallback. Compare against real rendered pixels, including group geometry and traversal, not declared fixture boxes.
- Pixel/metadata consistency across seek races, rebuild generation, project close/reopen and preview swap. Reject mismatched request/frame/session and reselect or fall back visibly. Do not select new metadata against old image.
- Source registration resolves exact current immutable source bytes; changed spans/hash, deleted IDs, duplicate IDs/anchors and path escape fail clearly. Retrieval then expands containing impl/imported helper/asset/token dependencies; this requires the separate deterministic Rust syntax index in M5, not marker-only snippets.
- Real generated project and assembled offline SDK support title click → source retrieval → provider edit → validation/review with before/after evidence. Preserve M4 scene/range contracts and broaden shared-helper validation. Native display/provider/platform qualification remains distinct from unit evidence.

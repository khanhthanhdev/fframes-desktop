fframes Studio · how it works

An agent writes code. Studio decides what counts.

An agent is fast and sometimes wrong. Studio is built so that being wrong is cheap.

01 · Checks

Five filters on the way up

Captured twice, built, inspected, optionally reviewed, then written in one atomic step. Anything that fails stays a draft.

Undo  Undo and per-file revert pass the same checks. A revert is refused if the file changed since.

02 · Grounding

From a pixel to a line of Rust

Every preview frame comes with a map of its objects. A click finds the topmost one and the source anchor the code registered.

let title_key = EditorObjectKey::new(key, "starter-title", "headline", "primary")
    .and_then(|key| key.with_source_anchor("src/lib.rs", "render_frame", Some(..)));
let title_id = title_key.render_id();
// in render_frame
<g id={self.title_id.as_str()}> … </g>

03 · Tools

Nine tools, all read-only

The agent can look at the video it is changing. It cannot run a shell, write a file or export.

  • project_context
  • selection_context
  • source_lookup
  • timeline
  • render_frame
  • render_strip
  • inspect
  • style_context
  • build_status
  • shell · write · exportnot available

04 · Preview

The preview swaps only when it is whole

The old build keeps playing while the new one is prepared. Worker, frame and audio switch together, at your playhead.

Renderer  Skia on the GPU when one works, the CPU renderer otherwise. The CPU renderer cannot run shaders, and Studio shows that as a warning.

05 · Containment

A fence around the agent

A job object on Windows, a process group elsewhere. If Studio sees one of its processes escape, the agent’s work is refused.

06 · Recovery

Crashes recover, old files stay put

After a crash Studio returns to the last accepted revision and offers the draft. A file from an older Studio is refused and left byte for byte.
